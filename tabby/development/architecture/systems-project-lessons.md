# Lessons from systems projects, in Python and where Python stops

Each row is a habit from a well-run C, C++, Rust or Zig project, the workload it solved there, and what it becomes here. Python first; the native column applies only when the project already has native code or a profile has shown Python cannot do it ([native-extension-architecture.md](../library/native/native-extension-architecture.md)). Name your workload before adopting a row ([design-under-real-limits.md](design-under-real-limits.md), last section): a rule that fixed a database's problem may not be yours.

| Habit (source) | Solved | In Python | Native, when Python cannot |
| --- | --- | --- | --- |
| **Fail the Nth operation** (SQLite's allocator and file-system hooks) | Recovery code that never runs in tests | Put I/O, the clock and allocation-like calls behind a small interface; a fake raises on call N. Run the operation for N = 1, 2, 3 ... until it succeeds, and after every run check the invariant (the file parses, the totals add up, no handle leaked). Then fail every call from N on | Give the core an allocator and an I/O table the caller can replace; test builds install a failing one |
| **Test through the public surface** (DuckDB's SQL test files, SQLite's TH3) | Tests that break on every refactor | Cases as data (input file, expected output) run by one small driver; assert on results, not on private calls. A refactor then changes no test | The same case files run against the native and the Python reference |
| **A second implementation as the oracle** (SQLite against other SQL engines) | Bugs both the code and its tests share | Compare against the stdlib, a slow obvious version or another library on the same inputs; see differential tests in [test-rigor-property-and-release.md](../testing/test-rigor-property-and-release.md) | Keep the Python original as the reference ([native-porting-a-function.md](../library/native/native-porting-a-function.md)) |
| **A narrow, versioned boundary** (curl's frozen public API; DuckDB's unstable C++ internals behind a stable C and Arrow surface; Ghostty's opaque handles) | Callers that break on every internal change | Public names in `__all__`, everything else underscored; the native module is private (`_core`); extend with keyword-only parameters, not new positional ones ([public-api-design.md](../library/shared/public-api-design.md)) | Opaque handles with getters and setters keyed by an enum, not one function per field; sized structs and reserved padding; symbol versioning; an ABI diff in CI ([native-zig.md](../library/native/native-zig.md)) |
| **Shared-nothing** (Seastar, ScyllaDB) | Locks and cache contention between workers | Split work by key; each worker owns its shard outright and receives work through a queue; results come back as values ([threads-processes-pools.md](../code/threads-processes-pools.md)). Assumes cores you can dedicate | Thread per core with explicit message passing between cores |
| **Know the cost model of the engine you call** (ripgrep and RE2's linear-time matching) | Input that makes a "usual" tool explode | Python's `re` backtracks, so a crafted pattern or input can take exponential time: use a linear-time engine (`google-re2`) for untrusted patterns or input, and a plain `str.find` before a regex for a literal. Say what the fast engine lacks (no backreferences) and keep the fallback explicit, not silent | The Rust `regex` crate behind the same signature |
| **Fix the shape at start-up** (Hubris's build-time task list; TigerBeetle's allocation at start) | Failures that appear only under load | Build pools, caches and routing tables once at start from validated config, with sizes set; after that the hot path allocates no new kinds of resource and cannot be reconfigured | Fixed-capacity structures sized at init; failure at init, not mid-request |
| **Separate privilege, restart the part** (Firecracker's jailer; Hubris restarting a driver task) | One bad component taking down the whole | Run risky work (untrusted files, plugins, converters) in a child process with a timeout, a memory limit (`resource.setrlimit`) and a scrubbed environment; the supervisor restarts it. Never `eval` or `exec` untrusted input ([input-and-secrets-security.md](../code/input-and-secrets-security.md)) | seccomp or Landlock filters, namespaces, dropped capabilities |
| **No hidden threads or allocators in a library** (libghostty-vt) | Embedders who cannot control the host | A library starts no thread, no event loop and no connection at import; the caller passes the executor, client or clock | The caller supplies the allocator; the core spawns no threads |
| **Heavy parts load on demand** (DuckDB's extensions; a core with no dependencies) | A big install for a small use | Optional dependency as an extra, imported inside the function that needs it, with an `ImportError` that names the extra ([choosing-dependencies.md](../dependencies/choosing-dependencies.md)) | A separate loadable module |
| **Simulate the world, deterministically** (FoundationDB, which TigerBeetle's simulator follows) | Distributed and timing bugs that appear once a year | Take the clock, randomness, network and disk as parameters; one seed drives a run, and a failure prints the seed so it replays exactly. Swap in fakes that drop, delay and reorder; check the invariant at the end ([test-rigor-property-and-release.md](../testing/test-rigor-property-and-release.md)) | Run the real core inside the simulator, with no threads of its own |
| **Never break what callers observe** (the Linux kernel's rule about user space) | Users who cannot rebuild their programs | Treat what callers can observe as API: result order, error types, even a bug they rely on. Fix a bug that callers rely on behind a flag or in a major version, and say so in the changelog ([public-api-design.md](../library/shared/public-api-design.md), [deprecation-and-migration.md](../workflow/deprecation-and-migration.md)) | Never change a symbol's meaning; add a new one |
| **Break on purpose when you own every caller** (BoringSSL promises no stable API) | A library kept compatible for callers who do not exist | An application, or a library whose users all pin it and move together, may rename and remove without a deprecation cycle: change the callers in the same commit and let the type checker find them. If any caller is outside the repository, use the previous row | A private core crate or C library whose only user is the binding |

## When to break an API

Ask who the callers are. Callers you cannot see or rebuild (a published library, a file format, a wire protocol, a symbol in a shared object): compatibility is the cost of having users, so deprecate first. Callers you can list and change in one commit: breaking is cheaper than carrying the old name. Never decide this by taste; decide it by finding the callers.

## Evidence is mixed: verify, do not assume

- Memory-safe languages remove whole classes of bug, not all of them. Mature C projects with heavy fuzzing and static analysis still ship memory bugs; Rust still fails inside `unsafe` and at the foreign-function boundary. A tool or language is a reason to look less often in one place, never a reason to stop looking at the seam: treat every call into native code as input you validate on the way in and check on the way out (Miri and loom: [native-rust.md](../library/native/native-rust.md)).
